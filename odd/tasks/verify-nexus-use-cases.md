# Verify Nexus use cases before adding features

## Decision and evidence rules
Scope: existing Nexus behavior only; do not build a Pi right sidebar. Keep the modular monolith. No blanket `tests/run_all.py` or browser E2E run until imports, environment, sandbox cleanup and external effects are isolated. Never use real accounts, personal files, databases or devices as fixtures without the owner's scoped approval. Avoid growing monolithic test files; organize by responsibility/CU, not arbitrary line counts.

Project TDD configuration: `openspec/config.yaml:44-49` records `strict_tdd: true` and canonical `.venv\Scripts\python.exe tests\run_all.py`; Engram `sdd/nexus/testing-capabilities` agrees. This broad runner is currently unsafe, so only preflighted standalone suites may execute; a pure test-file relocation has baseline/parity evidence rather than a fabricated behavioral RED. Do not infer that a full green result exists.

For each CU record: intended behavior → actual route → controlled input → observable result → failure path → evidence level. Evidence levels: **S** source exists; **M** mocked handler behavior passed; **I** real isolated process/HTTP/WS/browser plus sandbox persistence passed; **P** provider acknowledged and independently observed; **F** physical/user-visible effect observed. A mock can prove decisions and calls, not TV power, email delivery or provider data. A user report is valuable but separately labeled **R**. Unrun tests do not count as passing.
