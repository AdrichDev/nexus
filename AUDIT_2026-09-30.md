## 2. Security

### P1 — Historical potential chain (CRITICAL) [V baseline code]

This is a baseline code-level risk hypothesis, **not a demonstrated browser exploit**. On the branch, NEX-1 guards tokenless loopback WebSockets by Origin/Host, preserving QR-token LAN/tunnel access; NEX-2 removes the free-text `open_app` shell sink. Focused HTTP/ASGI tests passed; physical clients and a public tunnel were not tested. The chain below describes `main` at `4a21760`, not current branch behavior.

**Chain:**
1. `backend/app.py:191-207`: the `/ws` endpoint treats any connection whose TCP peer is `127.0.0.1`/`::1` as "local" and skips the token check.
2. Browsers do not apply CORS to WebSockets. Any web page open in the user's browser can connect to `ws://127.0.0.1:8177/ws`, and the peer still looks local.
3. `backend/app.py:238-242`: a `{"type":"command","text":"..."}` message goes straight to `brain.process(...)`.
4. `skills/system_pc/skill.py:1227`: if the app name is not found in the index, `os.system(f'start "" {alias.get(low, app)}')` runs with the raw captured text. The `open_app` regex captures `(?P<app>.+)` with no filtering (`skill.py:226-230`).

**Also [V]:** there is no CORS, `TrustedHost` or `Origin` handling anywhere in `backend/`. The HTTP middleware (`app.py:134-175`) has the same "peer is 127.0.0.1 means trusted" assumption, so DNS rebinding is a related risk ([S] for exploitability).

**Baseline recommendations (historical; NEX-1/NEX-2 addressed the stated WS and `open_app` boundaries):**
- [ ] Validate `Origin` (allow only the HUD origin and the packaged app) and `Host` (`127.0.0.1:8177` / `localhost:8177`) on `/ws` and in the HTTP middleware.
- [ ] Add a test in `tests/` that a WebSocket connect with a foreign `Origin` is rejected.
- [ ] Fix P2 (below) so the sink is gone even if the gate is bypassed.

### P2 — Historical free-text shell sink (HIGH) [V baseline code]

NEX-2 replaced the free-text `open_app` fallback with shell-free launching and rejection tests. Other distinct, constrained `os.system` calls remain and are not covered by that claim. The locations and remediation ideas below are baseline notes, not a current list of active free-text sinks.

Locations: `skills/system_pc/skill.py:1202`, `:1227`, `:1287` (shutdown, constant string, lower risk), `skills/discord/skill.py:57`, `skills/games/skill.py:73`.

**Fix:**
- [ ] Replace with `os.startfile(...)` or `subprocess.Popen([...], shell=False)`.
- [ ] Restrict the fallback in `system_pc:1227` to a known allowlist (`alias` values plus URI schemes) and reject anything containing shell metacharacters (`& | ; < > ^ %`).
- [ ] Validate `aid` and `appid` as digits-only before building `steam://` URIs.
- [ ] The smart-router path `brain.py` (`_LLMMatch`, ~689-701) passes model-generated `args["app"]` into `match.group("app")` with no validation [S]; apply the same validation at the skill boundary.

### P3 — Telegram owner takeover (HIGH) [V]

`backend/core/infraestructura/telegram_bridge.py:84-93`: if no owner is set, the first chat to message the bot is written to `data/telegram_owner.txt` and becomes the owner.

**Fix:**
- [ ] Require a one-time setup code (or the existing `link_token`) as the first message before registering an owner.

### P4 — Unrestricted file permissions by default (HIGH) [V]

`backend/core/comun/config.py:134` sets `"perm_files": "todo"`; `backend/core/comun/permissions.py:31` also defaults to `"todo"`.

**Fix:**
- [ ] Default to `sandbox` or `carpetas`; make `todo` an explicit opt-in.

### P5 — Token exposure and Android transport (MEDIUM)

- [V] The QR URL carries `?token=`, and the middleware accepts `request.query_params["token"]` (`app.py:161`). Uvicorn's access log can capture it unless `--log-level warning` is set. [S] `desktop.py` sets it; the dev command in `CLAUDE.md` does not.
- [V] `movil/AndroidManifest.xml:23`: `usesCleartextTraffic="true"`.
- [V] `movil/MainActivity.java:340`: `MIXED_CONTENT_ALWAYS_ALLOW`.
- [S] `frontend/mobile.html:156`: token stored in `localStorage` and sent in query strings.

**Fix:**
- [ ] Prefer the `x-nexus-token` header or the cookie over the query string.
- [ ] Add a `networkSecurityConfig` that allows cleartext for LAN hosts only; drop `MIXED_CONTENT_ALWAYS_ALLOW`.
- [ ] Force `--log-level warning` (or a redaction filter) on every launch path.

### P5b — Other security notes [S]

- [ ] The local/remote decision depends on `cf-connecting-ip`/`x-forwarded-for` being present when traffic arrives through a tunnel (`app.py:136`). It is a single point of failure if the tunnel type changes or a reverse proxy is added. Add a defense-in-depth signal.
- [ ] No active prompt-injection-to-execution path was found: `process()` is only called from trusted human channels. This is by convention, not enforced. Consider a `trusted: bool` flag on `process()` before any skill re-feeds scraped content into it.
- [ ] `requirements.txt` uses `>=` only, with no lockfile or hashes.

### Secrets check [V]

- No secret-like file is tracked (`.env`, keystores, `*.jks`, `secrets*`, `google_token*`, `google_credentials*`, `telegram_owner*`, `*.pass`, `*.db`, `data/`).
- None was ever added in git history (name-based scan of `git log --all --diff-filter=A`).
- Note: the check is by file name. A secret pasted inside an ordinary tracked file would not be detected; Trivy in CI covers part of that.

### The single failure [V]

`test_la_marca_de_origen_sigue_mandando` ("previsualizar(): con marca de origen NO se usa el segundo camino").

- Cause: `backend/core/dominio/purga.py:326` calls `filas_ligadas_a_nota` only `if memory.pg.online`. The test mocks that function (`tests/test_purga.py:681`) but never sets `online`, so with no Postgres the mock is never reached.
- Classification: environment-dependent test, **not** a product bug.
- [ ] Fix the test: force `mem.pg.online = True` inside the `try` block (and restore it), so it passes with or without Postgres.

### Gaps and weaknesses

- [ ] **No tests** for `voice_cycle.py` (`VoiceTurn`, `_reserve_turn`, cancellation, `_busy`). [S] (CodeGraph also reported no tests within 3 caller hops [V]).
- [x] Baseline lacked `/ws` authorization tests [S]. NEX-1 added focused regressions for foreign/missing/null Origin, local access and QR-token remote paths; sandbox HTTP 74/0 and live ASGI WS 7/0 passed. Physical clients/public tunnel remain untested.

- [ ] Check date-sensitivity of `test_calendario_por_fecha.py`, `test_eventos_varios_dias.py`, `test_eventos_google_rango.py` (they compute `date.today()` at import). [S] They passed in this run, which is not proof they are stable on other weekdays.
